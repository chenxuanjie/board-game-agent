# 桌游目录可用性与启动恢复

2026-10-19，源码已实现；未构建、发布或更新 NAS 部署。

桌游目录不是应用启动的硬依赖。Web 的权威目录在同源服务上，初始化
本机配置与会话后即允许进入应用，目录在独立任务中加载。Windows/Android
启动读取本机/内置目录，读取失败也进入应用，保留局部错误与重试入口。
账号隔离、存储恢复等基础初始化错误仍由原启动错误页处理，不以默认个人
数据掩盖失败；该错误页不再把所有基础错误描述成资料加载失败。

## 状态与数据边界

- AppController 的 catalog 分支独立管理 idle/loading/success/empty/failure。
  完整读取并校验后才替换游戏列表；失败保留最后一份可用列表。
- Web 始终使用服务器发布目录，不用内置目录掩盖 404、断网或格式错误。
  已打开页面的旧列表可保留；当前没有新增跨浏览器重启的离线目录持久化。
- 无目录时不改写每日推荐历史、不清空已恢复的桌游会话选择；收藏与私人数据
  保留原有账号隔离。通用 AI、账号和设置不依赖目录加载成功。
  通用助手的知识库模式在目录不可用时置灰，原因按需显示，不阻断普通问答；
  保存的知识库偏好不被临时故障覆盖，见 [助手界面](assistant-workspace-design.md)。
- retryGameCatalog 仅重试目录，不重跑应用初始化、登录或清空浏览条件。
  相同账号/语言/资料源的在途请求合并；旧账号、旧语言和旧资料源的迟到结果
  不覆盖当前列表。Web 网络目录每轮有 25 秒总预算，HTTP 请求仍遵循原服务
  超时；总预算超时不宣称所有底层请求已立即取消，其后结果不会被提交。
- 关闭页面服务、控制器或切换账号时结束目录等待与计时器；底层资料服务继续
  使用原有取消边界。单张图片/文档失败仍归各自位置反馈，不触发全屏启动失败。

## 提示与恢复

所有主题首页使用 LibraryCatalogStatus：左侧主题 error 色感叹号，轻色底，
简短说明，右侧重试和关闭。宽屏单行，窄屏/大字折为文案与操作两行。
关闭只隐藏首页本次故障提示；连续失败或后台轮询不重新弹出，直到目录真实
恢复成功后重置。之后发生的新故障才重新显示。

桌游库同样使用该状态，但不提供关闭，持续保留重试入口。首次加载无目录时
显示局部加载状态，失败不显示为正常“没有找到桌游”。有旧内容时保留网格。
后台 Web 资料检查成功后，即使目录版本未变，也会重试此前未成功加载的目录。
提示恢复只代表目录重新可用，不代表 PDF 已下载、账号已同步或资料完整检查完成。

## 验证与回退

catalog_availability_test.dart 覆盖同源服务的模拟 HTTP 404、不等待网络的 Web 初始化、
原生目录失败、重试合并、保留列表/浏览条件/会话选择、关闭语义、后台恢复、
超时迟到结果以及 320/1440 dp 的 150% 字号提示与各主题实际应用外壳。
资料更新和账号导航沿用既有回归用例。测试替代服务/平台插件，不等同于三端
真实安装包或 NAS 部署验收。

无需数据格式迁移；关闭状态仅本次运行内存保存。回退本次改动的控制器和共用
提示接线即可恢复原行为，不需要删除本机或 NAS 数据。
