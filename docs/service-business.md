## 运行链路

原生使用 `/v1/apps/board_game_agent/`；Web 使用同源 `/api/v1/apps/board_game_agent/`，同步流走 `/api/powersync/`；入口去掉 `/api` 后转发给同一个后台。PowerSync 原生连接沿用现有环境/Windows 代理策略。Web 部署仍按用户要求暂缓；没有恢复旧 Python Web 账号网关。

| 用途 | 新链路 |
| --- | --- |
| 登录、恢复、退出 | 共用账号 API，固定应用 ID；访问令牌只在内存中，续期凭据在独立安全存储 |
| 公开桌游、规则与图片 | 匿名 `/library` 发布清单和 `/library/files/assets/...`；与登录身份、NAS 密码无关 |
| 收藏、最近浏览、偏好、聊天、想玩票 | 账号独立 PowerSync SQLite；上传 `/sync/upload`，下载由签名应用流控制 |
| 评论、删除、点赞 | `/community/commands`；本机持久保存命令及幂等 ID，服务端确定作者与权限 |
| 评论、评分、收藏/想玩汇总 | 公开 `/community/comments/{game}`、`/community/statistics`；不下载其他人的私人数据 |

未登录可以保存应用服务地址、浏览公开资料，并继续使用自己提供的模型地址与 Key。收藏、投票和评论写入需要登录。设备语言、主题、BYOK 密钥、搜索/展示状态、评论草稿及 AI Run 轨迹保存在本机；它们没有被整个打包上传。Loomex 接入属于阶段 4，本轮未实施。

## 个人数据与失败处理

- `BoardPersonalStore` 是登录后已接入业务的唯一持久来源。`PreferencesService` 与 `ConversationStore` 直接使用它，不再通过一套文件日志投影、双写到另一套偏好/聊天存储。
- 数据库文件按应用、服务 origin、用户和数据集划分。新数据库从空数据开始；旧 NAS 日志、旧收藏/聊天文件不探测、不转换。游客自己的本机模型会话不会自动上传到账号。
- 收藏/最近浏览按游戏分行，投票按活动和游戏分行；聊天会话和消息分别存表；新主题与消息使用 UUID，时间按 UTC 保存，避免设备时钟/时区造成冲突。一次本机聊天保存是 SQLite 事务，消息超限则整次回滚。网络上传按有界记录批次提交，其他设备可能逐步收到会话与消息，最终收敛。
- 相同记录按服务端接受顺序裁决；偏好携带明确修改字段，不用离线旧快照覆盖另一设备刚改的其他字段。删除使用墓碑。服务器记录回执，响应丢失后重试同一 ID 不重复写入。
- 只修改界面确实改过的行，不把未看见的其他设备记录当作删除。后台更新等到本机保存、语音与模型输出结束后再刷新展示。
- 登录完成只等待本机工作区准备，不等待第一次网络全量同步。断网、上传失败或 401 不清空数据库、队列和草稿；账号页单独展示同步错误，不能把它报成登录失败。
- 切换账号先停旧网络、排空旧本机写入再切工作区。迟到响应只能属于原实例，不能写入新账号。退出保留各账号的离线数据。
- 聊天只同步稳定消息、引用及失败后的可重试信息；模型 Key、认证头、原始 Run/工具轨迹与本机 checkpoint 不进入云端消息。

旧 FileStation 私人日志、公共账号文件、旧 Web 评论适配器、登录衍生 WebDAV 凭据与旧资料传输已退出客户端运行路径，相关实现与过时协议测试已删除。旧 `services/web_account` 部署目录仍是阶段 5 的待退役部署，不能用于新接口。

## 公开资料与部署前提

后台需要迁移 **0013**、注册模块及更新生成的 PowerSync 配置；仅重新编译客户端不够。另需管理员准备经过校验的公开资料快照，将其只读挂给 API，在应用配置中声明 `public_file_roots.library`。工具不自动创建真实 NAS 目录，也不从账号密码获得资源权限。

快照保留 `catalog.json`、`game.json`、资源 `manifest.json` 与显式文件清单；路径、大小和 SHA-256 通过验证后才提供文件。支持 ETag、HEAD、Range；大文件流式写本机暂存，校验后替换原缓存，内存读取单次限 64 MiB，文件下载限 512 MiB/5 分钟。新缓存按服务 origin 隔离，失败保留上次已确认缓存；账号退出不会删除公共缓存。配置新服务后不回退到旧 NAS 或旧规则正文。

完整服务端契约、准备命令和 Compose 字段见 [后台桌游业务说明](../../apps/app_data_service/docs/board-game-business.md)。不要重新生成私有 Compose 来轮换已有数据库密码或签名密钥；下次正式构建与部署时再更新匹配的 API 镜像、规则和只读挂载。

## 公共实时更新（2026-10-27 源码扩展）

有人修改收藏/想玩票、发布/删除评论、回复或为评论点赞时，数据库在同一事务中递增该游戏的公共版本。PowerSync 将游戏 ID 和统计/评论版本推给其他客户端；客户端收到变化后重新读取 `/community/statistics` 和当前打开游戏的评论，统计服务驱动已有排行重新排序。通知不包含某人收藏了什么，也不复制私人集合来计算总数。

- 游客和登录用户都使用独立公共 SQLite；按服务 origin 划分，与账号私人数据库分开。匿名 `/community/sync-credentials` 只签发 5 分钟、只用于公共同步的凭据，不授权私人读取或写入。
- 250 ms 合并连续变化，统计和评论版本分别处理；同类快照串行读取，读取过程中发生变化会再读一次，避免迟到的旧结果覆盖新结果。
- 评论窗口引用计数管理关注游戏；关闭最后一个窗口后停止刷新该游戏，保留待发送命令。断网保留已有结果，读取失败最多重试 5 次（1/2/4/8/16 秒），新变化、恢复前台或手动重试可再次触发。前台恢复和同步重新连接会补读最新快照；后台不承诺操作系统唤醒推送。
- 退出、切换账号或服务会关闭旧公共订阅，旧响应仍受账号代际保护。公共更新失败单独提示重试，不报成登录失败；不添加调试弹窗。
- 此扩展需要新客户端、新 API、0013 迁移和配套生成的 PowerSync 配置。PostgreSQL/PowerSync 基础镜像无需升级，Web 同源转发部署仍待处理。没有构建或部署本轮产物。
