## 1. 开发流程与范围

1. 开始前查看 Git 状态、相关实现、已有组件与测试，识别本次修改和已有未提交工作。不得覆盖其他任务的改动。
2. 首轮实质修改前简述用户任务、影响平台、复用组件、数据与账号边界、加载/失败/取消状态、验证方案。小任务可简写，不额外增加审批或例行文档。
3. 先修行为、状态与数据边界，再处理布局和动效。先搜索现有能力，再新增实现；不以局部 UI 补丁掩盖共享设计问题。
4. 重大改版先在一个真实任务页面验证，再推广。按本次范围整理旧代码，不因制定标准重做无关页面、升级全部依赖或修改其他应用。
5. 完成后报告实际结果、验证证据、例外和未覆盖项。提交、推送、构建、上传与部署分别按授权执行。

设计从真实任务与主要操作出发，保持简洁，不为可能的未来需求建立空模块、配置开关或框架。工程常规选择自主完成；只有缺少影响结果的关键信息时才询问。

## 2. 工程分层与代码归属

| 层次 | 应承担的职责 | 不应承担的职责 |
| --- | --- | --- |
| 页面与编辑状态 | 展示、输入、焦点、选中项、草稿、导航与动作分发 | 直接 SQL、令牌续期、网络协议、持久队列及业务冲突裁决 |
| 应用服务与 Repository | 用例协调、事务、持久化、恢复、任务生命周期 | 弹窗、路由、依赖 Widget 销毁的业务提交 |
| 领域模型与规则 | 桌游、收藏、评论、资料版本、校验和合并规则 | 平台 UI、HTTP 细节和页面样式 |
| 公共客户端与平台适配 | 认证、请求、文件、更新、系统能力等真实通用机制 | 固定桌游 appId、桌游表结构及专属业务文案 |
| 主题、共用 UI 与 motion | 语义样式、布局策略、统一控件与动效 | 账号权限裁决、业务计算和持久化 |

依赖由界面流向应用服务、领域与基础设施，主题和基础组件不得反向依赖根页面。业务规则与校验保留唯一来源；持久化应可脱离界面测试。先在应用内部建立边界，有第二个真实消费者或已有合适公共接口时再提取公共包。

当前代码定位如下；这是实现地图，不表示现有代码已完成上述分层：

| 位置 | 归属 |
| --- | --- |
| `lib/main.dart` | 依赖装配、平台选择与启动接线 |
| `lib/app/state/` | 共享应用状态与用例入口；不得持续堆入所有新业务 |
| `lib/core/localization/`、`theme/`、`models/`、`platform/` | 文案、主题令牌、基础类型与平台适配 |
| `lib/features/games/`、`community/` | 目录、收藏、排行、推荐与评论 |
| `lib/features/library/` | 资料、资源源、检查、缓存和文档读取 |
| `lib/features/assistant/` | AI 配置、会话、Run、语音和规则问答 |
| `lib/features/identity/`、`settings/` | 应用服务账号、独立会话存储、个人数据切换；资料配置与身份分开 |
| `lib/ui/desktop/`、`mobile/`、`shared/` | 平台布局与共用 UI；共用业务状态与动作 |
| `services/web_account/` | `ai_app.py` 为独立 BYOK 模型代理；账号与资料统一转发共用后台，旧网关源码不进入新运行镜像，禁止发展第二套业务后台 |
| `test/`、`integration_test/`、`scripts/tests/` | 行为与布局、实际平台集成、打包部署工具测试 |
| `../apps/app_data_service`、`../shared_packages/app_client` | 独立仓库的共用后台与公共客户端；修改时读取各自规则 |

按功能归属放置代码，不按调用它的桌面/手机页面复制服务。不为对称性建立空 `models/` 或 `services/`。Dart `part` 仍共享同一 library 私有状态，按行数分文件不等于拆开架构。

常用接线入口：目录恢复在 `app/state/app_controller/catalog.dart`；资料检查在 `library_updates.dart`；账号在 `features/identity/services/account_service.dart` 与 `service_identity_gateway.dart`；个人业务在 `features/identity/services/board_personal_store.dart` 直接使用 PowerSync；资源缓存在 `features/library/services/remote_asset_service.dart`；配置保存/恢复在 `features/settings/services/settings_transfer_service.dart`；共用窗口在 `ui/desktop/desktop_window_frame.dart`。以上 `app/`、`features/`、`ui/` 路径均相对 `lib/`。

## 3. 产品、权限与长期演进

- 主要任务是浏览桌游、阅读资料、规则问答及个人收藏/会话。每个任务区域突出一个主要操作，次要信息不能抢占主操作。
- 新架构采用共用后台与账号、应用业务隔离；同一账号可以拥有多个应用的数据，不能互相读取私人业务。
- 新桌游库的全部资料公开，个人功能需登录。用户自带 API 地址与 Key 可在未登录时调用模型；登录后将服务端统一提供的 Loomex 作为默认模型服务选项，同时保留添加、选择其他自定义模型服务的能力。Loomex 不作为唯一选项。这些是接入目标，当前完成范围见末章。
- 当前不提供在线规则编辑器，不以本轮重构新增编辑、审批、角色分配或配额系统。资料整理与发布走受控工具流程，区分原始资料和派生内容。
- 长期实现保持单一方案：不新增无必要的旧协议回退、双写、旧存储探测、迁移开关或仅为旧调用保留的包装。选择新路径后，删除被替代的重复实现并更新调用者与测试。
- 新业务从新数据开始，旧数据暂存；完整验证后再按明确授权统一删除。删除兼容代码不授权删除真实数据，也不授权清空离线队列或 NAS 目录。
- 公共核心只承载跨应用机制；每个应用有明确模块、类型化业务表、路由、权限与同步声明，不把所有业务塞进通用 JSON 表，也不为每个新应用修改登录核心。

## 4. 界面、尺寸与无障碍

### 4.1 平台依据与项目取舍

本节按已确认方向设计：**统一产品外观、适配各平台操作习惯；交互层采用更明显的玻璃与弹性；页面可按任务选择尺寸和效果；可用性与降级要求必须满足。**不维护 Apple/Android 两套完全不同的产品皮肤，也不把跨平台 Flutter 效果称为 Apple 原生 Liquid Glass。

下列为 2026-10-26 核查的官方依据。它们持续更新，涉及 SDK 或平台新能力时重新核查实际版本；参考其行为与组织方式，不复制品牌、系统专属字体或未支持的 API。

| 官方来源 | 参考内容 | 本工程的取舍 |
| --- | --- | --- |
| [Apple HIG：Layout](https://developer.apple.com/design/human-interface-guidelines/layout) | 内容层级、分组与自适应组织 | 保持桌游、封面与规则资料为内容重点，窄宽屏分别组织任务 |
| [Apple HIG：Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons) | 操作层级、命中区域与按压反馈 | 图标外观与可点击区域分开；不把 Apple 的 pt 数值直接当 Flutter 像素 |
| [Apple HIG：Materials](https://developer.apple.com/design/human-interface-guidelines/materials) | 导航/控件与内容的材质层次 | 交互层玻璃明显；少量展示卡可用普通磨砂材质，这是项目选择，不把内容卡称为系统 Liquid Glass |
| [Apple HIG：Motion](https://developer.apple.com/design/human-interface-guidelines/motion) | 有目的、随输入变化且可减少的动态反馈 | 空间变化有弹性，阅读与结果状态稳定；不为展示效果延迟操作 |
| [Android：无障碍](https://developer.android.com/guide/topics/ui/accessibility/apps) | 触控目标、对比度、语义与不同输入方式 | 触控目标采用项目统一底线，精确指针界面可有独立密度 |
| [Android：窗口分级](https://developer.android.com/develop/adaptive-apps/guides/use-window-size-classes) | 依据可用窗口，分别考虑宽高 | 页面按实际容器与文字缩放组织，不用设备型号决定布局，也不机械覆盖所有主题断点 |
| [Material 3：组件](https://m3.material.io/components)、[动效体系](https://m3.material.io/styles/motion) | 组件语义、交互状态及 standard/expressive 动效思路 | 采用可靠的 Flutter Material 组件与可验证的动画实现，不将 Compose 的能力写成 Flutter 已支持 |

Apple 按钮指南通常建议 44×44 pt 的命中区域，Android 触控建议至少 48×48 dp；本项目触控默认至少 48×48 **Flutter 逻辑像素**，这是跨端项目选择，不是 pt/dp/截图像素之间的直接换算。桌面鼠标和窗口专用操作可更紧凑，但同一控件在触控场景仍须可达，不能以缩小命中区换取排版。

### 4.2 文案、主题与页面自由

- 标题、按钮和状态短而明确。空、加载、失败状态用一到两句话说明影响并提供下一步；删除重复说明、口号及开发讨论转成的常驻小字。
- 优先复用主题、`AppPalette`、`UiTokens`、已有控件与标准组件。页面可以按任务选择参考范围内的尺寸、圆角、密度与效果，无需逐个例外审批；相同语义在同一流程保持一致，出现稳定复用场景再收敛成主题/组件选项，避免另建相互冲突的全局体系。
- 下表提供设计起点，不是强制组件规格，也不是封闭上下界。实际内容、大字体、触控、键盘或窗口空间需要时自然增高、换行或改变组合；不要逐像素复制现有页面。
- 保留暖木书房、空间影院各自的识别特征。主题可以采用不同表面与形状，不要求所有页面套一种圆角；品牌与状态色语义保持稳定，不能仅凭颜色识别错误/选中。
- 桌面与宽屏 Web 继承打包的 Noto Sans SC 字体及对应许可，不临时指定 Windows 系统字体。字号、行高和字重从主题起步，测试实际字体与长中文/英文，不能用默认测试字体推断排版。

| 维度 | 项目参考范围 | 选择方法 |
| --- | --- | --- |
| 页面水平留白 | 窄屏 16–24，宽屏 24–32 | 先保证可读与任务密度，分栏按各自容器计算 |
| 元素与分区间距 | 常用 4、8、12、16、24、32、48 | 相关内容靠近，分区留白更大；不为了套档位制造空白 |
| 形状 | 普通控件约 10–16，卡片约 12–24，浮层约 20–32；胶囊按任务选 | 与尺寸、材质和分组匹配，嵌套边界避免视觉挤压 |
| 正文与辅助文字 | 正文/输入常见 14–16，辅助 12–14 | 密集桌面可较紧凑，长规则正文以舒适阅读为先；关键错误不用极小字 |
| 标题 | 分区约 18–24，页面约 24–32，展示标题按场景调整 | 通过层级、字重和留白组织，不把所有标题放大加粗 |
| 正文行高 | 常见 1.4–1.6 倍 | 根据中文、英文、段长和字体调整，不固定容器高度裁切 |

### 4.3 组件选型与尺寸参考

数值均指本工程 Flutter 逻辑像素；表中高度通常指视觉控件或基础行高，**不等于强制高度或命中区大小**。尺寸可自主选择，可用性要求不能省略。

| 组件/任务 | 常见起点 | 状态与适用边界 |
| --- | --- | --- |
| 主要按钮 | 高 48–56，水平内边距 16–24 | 一个任务区域有清晰主操作；加载与取消保持位置/外框稳定，文字放大可增高 |
| 次要/工具按钮 | 视觉高 36–48，图标 20–24 | 菜单、筛选和辅助操作可紧凑；触控通过布局与 padding 保持至少 48 命中范围，不重叠抢事件 |
| 输入框 | 单行视觉高约 48–56，多行按内容增长 | 标签、错误和帮助区域另行计入；焦点、错误、只读、禁用可辨，键盘下仍可见 |
| 列表行 | 单行约 48–64，多行约 64–88 起 | 内容增高优先；整行操作与独立按钮语义分明，长名称和错误不能被挤掉 |
| 筛选 Chip/分段选择 | 视觉高约 28–40 | 触控区域仍满足底线；支持换行或可发现的滚动，选中不只依赖颜色 |
| 卡片/分组 | 内边距约 12–24，间距约 12–24 | 按内容用途选择封面与比例，不强求所有卡片同高；密集列表不用层层套卡 |
| 菜单/Popover | 随选项收缩，常见宽 240–360 | 锚定真实入口，超出视口时重定位/滚动，Esc 与焦点返回有效，不为少量内容保留空白 |
| 简短说明/确认 | 宽屏常见最大宽 400–560 | 短说明或单一决策；危险动作与取消明确区分，不承载复杂表单 |
| 多字段编辑 | 宽屏字段区域常见 480–720；窄屏完整页面 | 显式保存、就地校验、草稿保护；不能把桌面大弹窗直接缩小搬到手机 |
| 底部面板 | 按任务与可用高度收缩 | 短选择可局部，多字段/键盘编辑改完整页面；滚动、关闭和主要操作可达 |
| 长文本与阅读区 | 宽屏常见限宽 640–800 | 规则、聊天与说明保持稳定阅读面，不把正文无限拉宽或放在强变化背景上 |
| 图片/封面/进度 | 保持资源比例与稳定占位 | 加载与失败分开；只展示真实进度，无已知完成量时用不定进度而非虚构百分比 |

导航、输入、选择、确认等优先复用标准组件的语义与状态。玻璃外观不能让按钮变得不像可操作控件；自绘控制仍需等价键盘、读屏和交互支持。

### 4.4 玻璃、表面与特效

本项目选择更明显的透光、模糊、高光和景深，但效果服务于操作层级；不能靠持续扫光、全屏折射或让正文晃动来强调“高级”。Apple 对 Liquid Glass 的功能层定位与这里的展示卡磨砂取舍分别表达。

| 区域 | 建议材质 | 约束 |
| --- | --- | --- |
| 导航、底栏、菜单、浮层 | 明显玻璃，可有透色、柔和高光、描边及浮起阴影 | 当前选中与焦点清晰，背景变化时文字/图标仍可读 |
| 主要控件与选中底板 | 按压、选择时增强玻璃与层次 | 不要求每个按钮都加独立模糊；避免多层高光争抢主操作 |
| 首页少量展示卡 | 可用普通磨砂/半透明内容表面，配合封面与留白 | 属于项目展示选择；不把整张可读内容卡称为 Apple 原生 Liquid Glass |
| 规则/聊天正文、长表单、密集列表 | 稳定实色或足够遮蔽背景的表面 | 不持续折射、变形或随背景改变文字对比，不把强玻璃铺满所有内容 |

- 材质参数按主题、背景与实际设备选择，不规定全局唯一模糊半径或透明度。至少检查亮图、暗图、复杂图、滚动经过文字及高对比场景，不能只对一张海报调效果。
- 优先共享材质容器、限制滤镜作用范围，避免长列表每项独立模糊、嵌套大面积模糊或叠加过多实时阴影；不是每次滚动都重绘全屏滤镜。具体优化用实际测量验证。
- 降级顺序优先缩小模糊区域/减少叠层，再改半透明或实色；保持原构图、命中区域与操作状态，不通过删功能、隐藏焦点或缩小文字换性能。
- 后续效果实现应提供可关闭透明/玻璃效果的入口，并核对实际平台辅助设置；系统减少透明度/高对比与减少动画分别处理。不假定所有平台或当前 Flutter SDK 都有同名 API，不能把 `accessibleNavigation` 当成降低透明度开关。
- 当前尚未完成全平台减少透明度适配；本节是后续实施要求，本轮文档修改不等于已经新增效果开关或原生玻璃能力。

### 4.5 交互状态、输入与无障碍底线

| 状态 | 必须能辨认的反馈 |
| --- | --- |
| 空闲/悬停/聚焦 | 可操作层级清楚，鼠标悬停与键盘焦点分别可见；悬停不能是发现功能的唯一途径 |
| 按压/选中 | 即时回应输入，选中保留明确的文字/图标/形状语义；不只靠一瞬间弹动 |
| 禁用/只读 | 视觉与可编辑状态区分；原因必要时通过 Tooltip/长按或就地信息说明，不堆固定小字 |
| 加载/取消中 | 显示真实处理与下一步操作，重复提交受控；取消中等待真正收敛，不立即假装空闲 |
| 成功/失败/空数据 | 本地写入、刷新与同步结果分开；失败保留输入和重试，空状态不伪造数据 |

- 触控命中区域默认至少 48×48，图标可较小；精确指针密度与窗口控制有各自热区，不能直接当手机标准。不得靠重叠透明点击区域满足尺寸。
- 支持系统文字缩放，不限制缩放掩盖溢出；字段、错误与主要操作在键盘下可见。普通文字对比度目标至少 4.5:1、大字号至少 3:1，依据实际分类与工具检查；玻璃背景也须验证。
- Tab、Enter/Space、Esc、Android 返回与 Web 浏览器返回遵循同一业务保护，并保留平台习惯；面板关闭后焦点回入口，手势提供可发现的替代操作，读屏不重复朗读装饰层。
- 返回、关闭、遮罩、切换记录统一经过未保存修改保护；无修改不多问，有修改保留继续编辑/放弃选择。重建、窗口变化和辅助说明不丢草稿。
- 列表返回保留搜索、筛选、排序和稳定条目锚点；加载/失败占位不跳布局。登录和取消登录继续使用同一个主按钮，动态条与按钮状态真实对应，不能以重画按钮掩盖任务未结束。

<a id="motion"></a>
## 5. 动效与交互连续性

### 5.1 动态风格与实现边界

目标是**空间运动更有弹性、触感与连续性，阅读内容稳定**。借鉴 Apple 的输入反馈与空间层次，以及 Material 的 expressive 物理动效思路；不强制所有页面使用同一条曲线或同一个毫秒数。

移动、尺寸、形状和拖动落位可采用弹簧；颜色、透明度、文字与进度采用稳定过渡，不使用过冲。弹簧依据位移、输入速度与阻尼收敛，不用固定计时器代替物理状态；手势释放后承接当前速度与位置，反向或新操作从当前状态继续，不能瞬间跳回起点。

官方 Material 新物理动效体系的 Flutter 实现状态在本次核查中仍标记 Unavailable；现有 `useMaterial3: true` 不等于已具备完整 M3 Expressive。当前 `AppMotion` 主要是固定时长与 Cubic 缓动，新增物理效果须先核对项目实际 Flutter SDK，复用可用框架能力并验证，不照搬 Compose API 或宣称本轮已实现弹簧系统。

### 5.2 场景与参考范围

下表是项目设计起点，不是 Apple/Android 官方参数，也不是每个页面必须逐项采用的规格。弹簧的时间指视觉收敛目标，不是延迟业务或强行截断模拟的期限；开发时根据对象大小、距离和设备证据自主调整。

| 场景 | 动态方式与参考范围 | 必须保持的行为 |
| --- | --- | --- |
| 悬停/聚焦 | 约 100–180ms 的颜色、描边或局部层次变化；卡片可轻抬约 2–6 | 焦点不挤占布局，触屏不依赖 hover，离开后回到当前目标 |
| 主要按钮按压/释放 | 按下即时，参考 80–140ms；可缩至约 0.96–0.99，释放以短弹性恢复 | 命中区稳定，不缩放整页，不延迟触发动作；减少动画时保留明确按压状态 |
| 导航选中/分段切换 | 底板位置/形状连续移动，可明显弹性，常见视觉收敛约 180–320ms | 选中与页面状态立即切换，不叠加第二套组件反馈或排队播放旧选择 |
| 菜单/面板开合 | 尺寸/位移可弹性，进入常见 200–360ms、退出约 140–240ms；透明度独立平滑 | 锚点明确，不越出可用窗口；关闭和焦点生命周期不依赖装饰动画猜测 |
| 展开/折叠 | 容器自然尺寸变化，常见 180–320ms 或短弹簧 | 聚焦字段与操作可见；正文不被拉伸，快速反向操作不中断业务状态 |
| 拖动与落位 | 拖动跟手，释放承接速度，常见落位收敛约 220–450ms | 稳定条目 key、行尺寸、滚动锚点和非拖动替代操作；不把装饰位置当已保存顺序 |
| 封面与卡片衔接 | 真实起终点几何过渡，可采用有控制的弹性，常见 240–450ms | 没有真实来源位置就用普通转场；账号/窗口/目标改变时取消，不拦截点击 |
| 收藏/点赞等确认 | 局部图标可轻弹，常见 180–320ms；初始可试约 1.03–1.10 的短暂放大 | 初次读入不庆祝，重复动作受控，失败回滚已确认状态；具体既有效果见实现基线 |
| 消息与内容出现 | 短淡入或小位移，常见 120–220ms | 历史消息与流式 delta 不重播；正文、代码和长规则不跟随弹性变形 |
| 数据/颜色/进度变化 | 稳定过渡常见 100–220ms，无过冲 | 数字与结果可立即读取，只平滑已知真实进度，不滚数、模拟打字或虚构完成度 |

明显弹性不等于长时间反复弹跳。空间过冲可先尝试约 2%–6% 的轻量比例，再按视觉对象调整；大型面板、可读内容与屏幕边缘优先更高阻尼。位移/缩放这些数值仅为试验起点，不适用于文字、颜色、透明度或决定业务成功。

### 5.3 连续性与业务边界

- 优先使用标准组件自带反馈；需要更强弹性时调整合适的容器或状态层，不在同一动作上再套一整套动画。可复用语义预设放共享 motion，场景参数可自主选择，不要求逐个例外审批。
- 动画结束回调不得触发保存、删除或同步，不为播完动画延迟真实完成。主工作区只挂载一个当前业务页面，装饰层不持有业务状态、输入或重复语义。
- 持续输入和快速连续点击追随最新意图，不让动画锁住下一次操作。路由本身的系统返回、滚动与手势机制优先保留，不为视觉统一重写整套平台导航。
- 稳定条目、历史消息、同页重建和流式 delta 不重播入场；图片首次真实解码后可渐入，已有图片刷新保留可用帧，不用计时器模拟加载。
- 封面衔接需要真实起点/终点；快速切页、窗口变化或账号变化时取消。紧凑端优先复用 Flutter Hero，源标签按实例隔离，不同时保留两套可操作详情。
- 收藏等乐观反馈仍受串行写入、防重复和失败回滚约束；图标弹动不等于远端确认。动态条、不定进度与确定进度按真实任务状态选择。

### 5.4 减少动态效果、性能与验收

- 读取运行中的实际平台辅助偏好；减少动画时停用弹簧过冲、形变、大位移、视差和自动重复运动，改即时变化或短淡变。保留文字、焦点、选中及必要进度；不能因停止动画隐藏操作结果。
- 减少透明度与减少动画分别生效：关闭玻璃后仍可有允许的动态反馈；关闭动画后仍可保留可读的静态材质。高对比、读屏开启不是同一个设置，不以 `accessibleNavigation` 直接关闭玻璃。
- 先验证一个代表性页面的弹性、玻璃、连续点击、键盘与减少效果，再推广。后台、不可见页面和已退出浮层停止无用动画与滤镜更新。
- 性能按实际设备 profile/浏览器证据判断；60Hz 约 16.7ms、120Hz 约 8.3ms 是每帧预算参考，不是 debug 或截图已通过的结论。效果无法稳定承载时优先减少模糊层数/范围与装饰，不影响任务完整性。
- 验收覆盖按压中取消、快速选中与反向开合、拖动释放、窗口/键盘变化、图片加载与流式内容，以及默认/减少动画/降低透明度/高对比组合。没有实际设备或偏好映射证据时写明未验证。

<a id="async"></a>
## 6. 异步任务、网络与取消

- 每个操作明确所有者、状态、重复点击策略、超时、取消、重试及结果提交条件。状态至少区分空闲、处理中、成功、空结果、失败；取消中不能立即假装已经结束。
- 分清单次 HTTP 超时、单入口期限、整次用户任务期限与后台预算，文案和诊断使用同一口径。多入口或多次重试不能把“每入口 45 秒”写成“整次登录最多 45 秒”。
- 等待、连接、读取与重试必须有界。耗时用单调时间；重试限制次数并可取消，身份/权限/格式错误不无条件重试。非幂等写入只有具备幂等键或可核实结果时才自动补试。
- 同一作用域的重复检查合并；明确刷新要求若不能由当前轮满足，应安排当前轮后的强制读取，不能静默返回旧 Future。个人投影在忙碌期间保留待刷新意图，结束后按间隔补跑；持续通知不能无限推迟已排定的刷新。暂停保留意图、恢复补读，账号切换及销毁失效旧作用域的定时器和收尾回调。
- 初始化只复用进行中或已成功的结果；失败后允许新尝试。已完成的恢复/服务阶段保持幂等，后台工作在必要阶段成功后启动，不能因重试重复注册监听或启动任务。
- 原生侧调用 Flutter 通道必须在平台线程执行。Windows 语音使用 SAPI 窗口消息通知并在平台 COM 线程读取事件，停止后失效本轮标识、释放识别上下文；不得让工作线程同步等待正在等待其退出的平台线程。
- 页面关闭、账号/应用/资料源/语言切换后，旧结果不能覆盖新状态。超时返回不等于底层请求已停止；需要真实中止传输，或明确隔离迟到结果并释放资源。
- 独立业务任务使用独立取消边界。取消排行读取不能顺带取消私人上传；退出账号则停止整个账号的工作。
- 启动先保证安全的应用外壳与独立服务可用。目录、图片或远端错误局部恢复；账号隔离、存储恢复等基础故障不得用默认用户或空列表掩盖，相关写入保持禁用。
- Windows 网络必须核对环境与系统代理，不能假定 Dart 默认读取系统代理；Web 核对同源、CORS、Cookie/CSRF、流式缓冲与浏览器缓存；Android 核对证书策略及实际平台数据库/网络拒绝路径。
- 日志记录任务 ID、阶段、耗时、尝试数及安全错误码，不记录密码、Key、SID、认证头、完整敏感 URL、私有正文或原始错误响应。

<a id="data"></a>
## 7. 数据、账号与恢复

- 持久化事实、读回状态和远端同步分别建模。写入事务成功后才宣布已保存；写入失败保留输入与重试入口。已提交但刷新失败显示“已保存，暂时无法刷新”，只重读，避免重复写入。
- 会话在调用模型前按真实存储记录的 UTF-8 字节预算校验并确认用户消息本机提交；拒绝的输入保留在编辑器，不启动模型。保存队列可吸收异常以便继续排队，但队列完成不等于持久化成功。更新交接、账号切换和可等待的服务销毁共用本地提交屏障：排空队列、重试脏会话并检查结果，失败保留内容与保存提示，阻止更新或切换；同步刷新不得覆盖未提交会话。屏障只等待本地提交，不等待远端上传确认，离线但本机已提交时允许更新。系统强杀无法依靠销毁回调保证保存。
- 持久化由显式命令触发，不放在 `build`、路由退出、动画或销毁回调。事务内不等待远端网络；需要排队的业务使用明确的持久队列与幂等标识。
- 批量导入先预览和完整校验，再提交事务或明确的恢复流程；恢复失败保留恢复记录，禁止以清空存储冒充修复。跨多个偏好/安全存储的写入不能宣称数据库原子事务。
- 缓存与源数据分开；读取失败不等于无数据。缓存不能跨账号泄露，退出立即隐藏私人数据，账号切换后旧任务、队列与浏览状态不能写入新账号。
- 公共数据只包含业务明确允许公开的字段；凭据、API Key、私聊和个人偏好不进入公共统计。公开资料权限与私人功能权限分别检查。
- 服务端同时绑定已验证账号与已登记应用；API 路径、应用标识与签名范围一致，禁止默认猜测应用。RLS、API 和同步流分别验证隔离，不能只靠 UI 隐藏。
- 数据库迁移显式审查，运行角色不得建表或注册任意模块；新应用新增自己的类型化模型、迁移、路由与同步声明。对数据库锁、连接和事务设置有界预算。
- 备份、回滚和清理只处理明确范围。源码 Git 回退不等于数据库、NAS 或离线队列已经回退；破坏性清理必须单独授权。

### NAS 操作边界

- 开发与诊断不得擅自修改 NAS 权限、所有者或真实账号目录，不删除、移动或重命名 NAS 文件夹。保留旧真实数据，后续清理单独授权。
- 新账号只提供应用身份，不派生 WebDAV 凭据，不初始化 FileStation 同步目录。公开资料由管理员准备完整快照并只读挂载，客户端不遍历 NAS 共享目录。
- 公共资料允许匿名读取；私人数据经应用 API、数据集权限和 PowerSync 处理，不能为了读取规则重新要求 NAS 登录。

<a id="content"></a>
## 8. 资料与资源发布

- 游戏身份、版次、展示元数据、原始资料、派生文本、索引与发布版本分开管理。保留来源、许可、适用版次及 AI 使用范围，不把不同版本规则无说明混用。
- AI 文件输入使用所选发布资源的实际正文，`source_url` 仅用于来源追溯，不能替代正文或作为失败回退。发送前校验文件 SHA-256，引用保存资源 ID、实际摘要、版次及可确认的发布水位；资料换版使相关压缩缓存失效，聊天历史及旧引用保留。资料按完整文件选取，不静默截断；预算同时计入 Base64、历史、指令、结构化输出 schema 与封装余量。当前账号通道上限 512 KiB、BYOK 工作流上限 16 MiB，预留 8 KiB SDK 封装空间并保留传输层实际字节检查；所有资料阶段共享累计 20 秒准备预算，读取有界且支持取消，超限或校验失败不得改读来源网址。
- 旧资料整理源使用 `catalog.json`、`game.json`、资源 `manifest.json`，仅供一次性导入与审计；客户端运行时直接读取 SQL 发布 API 和完整离线快照，不回读这些清单。发布版本、结构版本与每份 PDF 的内容摘要分别管理。
- 新资料库以类型化 SQL 元数据和内容寻址文件为来源：整理/导入先生成草稿，文件复核后由统一发布服务一次提交发布版本、条目映射和变化记录。客户端只接受完整发布版本，禁止绕过发布服务直接改当前版本；旧 JSON 仅用于一次性转换和审计，不作为新接口的运行时来源。
- 导入保留禁用、缺失、归档、来源/派生关系及历史检查记录；保存不等于公开或允许 AI 使用。未知附加字段先原样保存到 SQL 审计/原文并记录警告，后续再按业务类型化；身份冲突、非法必需字段及越级路径仍阻断。缺文件可保留登记但不提供失效下载，不自动清理旧真实资料。
- 资料启动导入可由 Compose 显式配置，成功后持久保存完成记录，普通重启不重新扫描。小文件可保留 SQL 原文字节、解码文本与 JSON 副本，逐份写入而非全库驻留内存；大文件继续由文件存储提供。原始资料源只读，自动导入仅写入专用资料卷，正常 API 不开放资料写入接口；日志列出实际提交结果，不打印正文或秘密。
- 先上传并核实资源文件，再提交依赖它们的配置和目录；文件不完整、空文件或路径不可读时不能宣布发布成功。缓存命中不能代替真实远端核验。
- 缓存先写临时文件，校验后替换；失败保留已确认数据与重试入口。完整性要求与检查算法分别声明，不把 ETag/mtime 相同说成逐字节一致。
- 不为检查未登记资源遍历 NAS 全盘；运行资料排除 `docs/others`。新数据整理不夹带旧数据清理。

### Android 资源边界

APK 不内置桌游 PDF、规则书、FAQ、知识正文、翻译、索引、研究素材或资料压缩包；`assets/games/<slug>/docs/` 一律排除 Android。只保留运行必需代码、字体、图标、界面图片、封面和轻量目录元数据。正文按需下载缓存，未下载时明确提示；公开访问目标不改变 APK 精简规则。

`pubspec.yaml` 使用平台范围，禁止声明整个 `assets/games/`、游戏根或包含正文的宽泛目录绕过限制，不通过修改已签名 APK 精简。构建时检查合并资源，交付前用 `scripts/verify-android-assets.ps1` 检查实际 APK 条目与大小。Windows/Web 资源是否保留按实际运行方式决定，不因 Android 排除规则误删其他平台资源。

## 9. AI 与 Agent 完整链路

### 9.1 复用与依赖

先区分协议适配、Agent 编排、RAG、服务商路由、UI 或持久化，再查相应成熟实现的源码、测试、文档与版本。优先复用官方 SDK、成熟库或独立服务；不能直接复用时记录具体的语言、平台、运行时、许可或边界原因，不以“参考过”代替实现。

| 能力 | 已确定的参考方向 |
| --- | --- |
| 协议、Run、工具与 trace | OpenAI Responses API、Agents SDK；Agents SDK 不假定存在官方 Dart 版本 |
| 长流程、暂停与恢复 | OpenHands、LangChain/LangGraph、LobeHub |
| 多模型聊天与流式 UI | LibreChat、Open WebUI、Vercel AI SDK；TypeScript 能力不能直接当 Flutter 依赖 |

每次实际采用时记录可追溯链接、版本、源码路径、许可证、依赖、平台限制、维护与升级风险；Dify、FastGPT 等须核查实际版本商用条款。复制代码保留版权及许可，不复制品牌和无关实现。同一能力只保留选定实现，不并存一套自研与一套未使用的开源接入。

### 9.2 完成条件

AI 功能必须覆盖完整用户链路，不能以静态卡片、demo 或单一成功路径标记完成：

- 请求创建、上下文选择、权限、模型能力与幂等标识。
- 流式事件顺序、去重、背压、delta 批量刷新、done/completed 收尾及受保护的原始事件留存；文本、工具、引用和最终答案分层。
- Run、阶段、工具调用与引用具有明确状态转换；会话、上下文、Compaction、轨迹及必要浏览状态持久化并版本隔离。
- 无状态 Responses 上下文只裁剪最新 Compaction 之前的内容，保留该压缩项及其后的输入、输出和新增轮次；仅最终采纳的成功阶段能提交窗口，失败、取消和未采纳阶段不得推进边界。缓存记录格式版本和可核对的聊天边界；旧格式、边界不匹配或超出缓存预算时弃用整个窗口，从现有最近消息重建，不删除聊天。当前缓存格式为 v2，单窗口上限 256 KiB / 512 项，回退窗口最多 12 条历史消息，不承诺无限历史记忆；回归覆盖三轮以上不连续压缩、压缩后输出、重启及流式/非流式一致性。契约参考 [OpenAI Compaction](https://developers.openai.com/api/docs/guides/compaction)。
- 超时、断网、4xx/5xx、鉴权、限流、不可用模型、解析失败、取消、重连、有限退避、恢复和完成去重。
- 失败保留 `_failureNotice` 的原因、尝试数、部分答案，以及已确认阶段的真实资料/引用进度；引用可追溯，不伪造来源或把未完成部分标为最终答案。
- 中间状态、工具参数、协议与搜索原文分层脱敏后展示；切换会话/账号后旧 Run 不得写入新 UI。
- 记录 runId、responseId、阶段、模型、请求次数、耗时、usage、引用数与错误码；凭据和私人正文不进入诊断日志。
- 覆盖协议顺序、故障注入、集成、布局/截图、长对话及压力场景；按变更风险提供相关证据、平台限制和回滚方法。

Flutter 交互优先复用现有 SDK/组件。既有动效参考 Fluent 2 Motion、Flutter Hero、Image.frameBuilder、PageStorage 与标准菜单/面板；沿用项目实际锁定版本与许可，升级时验证行为，不照抄过时 SDK 参数。

## 10. 同步、检查与更新

| 名称 | 真实含义 | 不能代替 |
| --- | --- | --- |
| 可用性检测 | 入口和实际读取权限是否可用 | 资料已完整检查、账号已同步 |
| 资料快速检查 | 轻量目录读取与差异比较 | 目录未变时的 PDF/图片内容检查 |
| 资料完整检查 | 比较目录及已登记资源的版本信息 | 全盘遍历或全正文 SHA-256 审计 |
| 账号同步 | 私人业务传输、公开记录发布与读取 | 资料更新、登录成功 |
| 应用版本检查 | 当前平台程序版本是否可更新 | 规则资料版本 |
| 会话验证 | 登录身份与授权是否有效 | 业务保存或传输成功 |

- 公开资料/程序发布以事务水位和公共订阅通知触发权威 API 补齐，不通过一分钟资料轮询或周期全库扫描发现变化。启动、前台恢复和手动检查保留；可用性与资料差异可复用同一有效版本响应，但各自结果分开表达。
- 自己的公开发布、公共排行读取、私人同步分别有状态、任务与恢复策略；私人失败不污染排行。个人选择、发布确认和远端统计分别表达，不盲写共享总数。
- 本机提交、持久队列、远端确认与界面投影分开；先保存业务和可恢复意图，再联网。进程重启、断线、重复提交和账号切换不能丢操作或重复计数。
- 失败保留最后完整结果，不能用部分扫描冒充完整排行；通知时间和历史更新数量不代表此刻实时检查结果。
- 资料 manifest 与安装包更新 manifest 分开。应用更新仅检查当前平台，下载/安装按明确操作执行；校验完整后安装，资料通知不打断正在进行的应用更新。
- Web 程序通过管理员更新部署，不展示 APK/EXE 检查或安装入口，不执行启动安装包检查；资料刷新独立工作。
- APK/EXE 默认使用应用服务的公开升级接口，游客可以检查和下载安装包。PostgreSQL 管理发布记录，独立文件存储提供安装包；不内置共享账号、NAS 密码或发布密钥。WebDAV 实现保留为显式备用，不自动回退或双写。客户端与发布器来源须配套，见 [游客程序更新](public-updates.md)。
- 安卓 NAS 实时更新提醒由用户开启，使用前台服务订阅公开发布水位，不依赖账号或 Google；受系统后台限制，无法保证持续连接或必达。范围和限制见 [Android 后台更新提醒](android-system-notifications.md)。

现有数值、协议与限制集中在 [实现基线](#implementation)，新后台接入时应替换对应说明和旧代码，不叠加另一套任务路径。

## 12. Git、构建与交付

- 分支、提交、推送与发布按本次授权执行；仅暂存已审查的相关文件，不夹带其他任务、凭据、签名材料、私有 profile、真实数据或构建产物。

- Android 的 IDE 同步、通用 Gradle 配置及 Debug 不依赖正式签名材料，Debug 使用开发签名。Release 在任务依赖链中校验正式配置字段和密钥文件，缺失或不可读时明确失败；禁止静默回退 Debug 签名或生成未签名交付，不能仅靠命令名称猜测是否需要校验。真实密钥及密码不进入测试夹具、日志或版本管理。

<a id="program-versioning"></a>
### 12.1 程序版本与发布批次

#### 范围与唯一来源

本轮只统一 APK、Windows 安装器、自有应用/后台镜像及辅助镜像的版本更迭。共用后台提供应用隔离的轻量发布登记：分配构建号、冻结来源、登记目标产物和发布状态。桌游资料发布与同步结构保持现有机制，不增加资料版本体系、管理界面或审批流程，也不改变匿名客户端的升级查询与下载协议。

每个应用独立维护版本，共享发布规则与工具。桌游助手以根目录 `pubspec.yaml` 的 `version: 主版本.次版本.修订版本+构建号` 为程序构建版本来源；APK、EXE、Web 应用镜像和发布清单从中读取。语义版本按本节选定，构建号由后台按应用统一分配，再由准备工具写入 pubspec；`release-batch.json` 随源码提交，只描述相同版本和服务端批次身份，不自行编号。私有 profile 保存交付环境和渠道，不另维护程序版本；平台配置、安装器模板和 CI 不手工保存另一份版本。独立后台使用其所属仓库的版本源，共用 API 对应 `app_data_service/pyproject.toml` 的项目版本，不与桌游助手共用一串版本号。

语义版本表达本次更新的影响，构建号识别一次正式发布批次；源码提交和产物摘要确认实际内容。端口、Compose 项目名、文件名时间戳、镜像 `nas` 标签均不作为程序版本，也不因版本更新而自动改动部署身份或地址。

#### 语义版本的确定

相对上一个适用的已发布版本审查本批次的全部变化，选择影响最高的一档，一次确定目标版本。已有发布意图时沿用已确定的目标，不因增加一个修复提交或补构建一个平台再次涨版本。提交类型可辅助判断，不能仅凭 `feat`/`fix` 前缀或改动行数决定版本。

| 更新性质 | 版本变化 | 例子 |
| --- | --- | --- |
| 修复、性能优化、保持原有使用方式的内部重构或打包优化 | 修订版本加一 | `5.0.0 → 5.0.1` |
| 新增可用功能或明显扩展能力，原有使用方式仍可继续 | 次版本加一、修订版本归零 | `5.0.1 → 5.1.0` |
| 明确改变使用方式、程序接口或持久化格式，造成不兼容 | 主版本加一、次版本与修订版本归零 | `5.1.0 → 6.0.0` |

内部重构规模大不必然升级主版本；单纯改文档、重复打包或重推已有产物不构成新的程序版本。每次正式发布说明版本选择及主要变化；存在无法判断的产品边界时再与用户确认，不为了填写版本机械新增功能。已交付版本不追溯改名、重写源码声明或移动其标签，本规则从后续发布开始执行。

#### 构建号与批次冻结

1. 新正式批次在编译前确定语义版本，由后台在事务中分配一次构建号。构建号在同一应用内保持递增，升级主版本、切换平台或更换渠道都不归零；编号超过本机声明、历史安装包发布记录和已分配编号的最大值。不同应用独立计数，多个发布入口不得各自计算下一编号；同一请求键重试取得同一批次，服务不可用时停止正式准备，不退回本机加一。
2. 准备工具写入完整版本与批次描述，审查并提交应用源码和实际 path 依赖后，再向后台冻结这些提交。批次描述不保存自身 commit，避免自引用。只构建 APK、只交付镜像或同时构建多端都只分配一次。各平台构建、打包、校验和上传只读取冻结版本，不在中途修改 `pubspec.yaml`。
3. 本地开发构建、plan、verify、dry-run，以及同一输入的失败重试不递增。重试沿用原批次；已分配并提交的编号不因失败回滚或另给不同输入使用，允许保留空号。
4. 先交付 APK，之后补 EXE 或应用镜像，应用源码与公共依赖相同则复用原批次。原目标的源码、依赖、工具链或编译配置发生变化，需要新的正式批次；新增目标的平台、架构、工具链与参数单独记录，不能用补平台掩盖源码变化。
5. 正式产物按应用、完整版本、平台、架构和交付类型区分。同一目标的已发布产物不可覆盖；重推同版内容必须核对原发布记录与 SHA-256/digest，内容不同则创建新批次。渠道只是指向产物，不因换渠道重新编号或重建未变化的产物。

本地 dirty 构建只能标为开发用途，记录 dirty 状态，不混入正式渠道；本地显示版本不是正式交付证明。版本比较按数值字段及既有升级协议执行，不能直接按字符串排序；Android 的构建号及 Windows 原生版本字段由发布工具映射和校验，不截断或静默改成其他版本。

#### 产物、镜像与来源标识

| 对象 | 标识规则 |
| --- | --- |
| Android | 完整版本保持 `语义版本+构建号`；APK 名为 `board_game_agent-<完整版本>.apk`，清单、安装包元数据及发布记录一致 |
| Windows | 同一批次使用同一完整版本；安装器名为 `board_game_agent-<完整版本>-windows-<架构>-setup.exe`，显示版本与原生数值字段由同一版本源生成 |
| Web 应用镜像 | 不可变标签采用 `<语义版本>-<构建号>-<提交前12位>`，完整提交、应用版本、平台和镜像 digest 写入交付记录；Docker 标签中的 `-` 只是对 `+` 的编码 |
| BYOK 辅助镜像 | 保留当前 `inputs-<sha256>` 输入寻址方式；输入未变则复用，记录其自身原始提交与 digest，不伪造为本次重新构建或改标成本次来源。仅辅助服务变化不推进客户端程序版本，组件分别记录来源 |
| 独立后台镜像 | 读取后台自身语义版本，不引入客户端构建号；不可变标签采用 `<服务版本>-<提交前12位>`，记录完整提交、平台和 digest。功能影响按同一语义规则判断，失败重试不递增 |
| 第三方镜像 | PostgreSQL、PowerSync 等保留上游版本与 digest，不随客户端版本递增或强制重建 |

| AI 新对话 | 同一助手范围复用一份空白工作区，未发送的输入只留在本机编辑状态，不进入历史计数或会话同步；有效发送后保存正式会话，失败提问保留以便重试 |
| AI 动效 | 切换对话只过渡当前消息区；首次发送允许只读欢迎层短暂退场，始终只有一个活动消息列表；回答操作与引用渐入展开，删除历史记录在写入成功后收拢；历史消息和流式增量不重播，输入控件保持挂载 |

空间影院工作区在 760 起使用宽屏业务构图，Web 保留场景浮窗、Windows 铺满实体窗口。新功能不得用手机页固定宽度居中替代应有的桌面组合。主题专项文档中的实现记录仅用于定位代码与历史差异。

### 13.4 程序版本管理的实现边界

2026-10-31 完成第二阶段源码接线。根应用仍声明 `5.0.0+55`，API 仍声明 `0.5.2`；开发修改不申请正式编号，不追溯重命名既有版本。本阶段未构建平台产物、提交、上传或部署。

| 入口 | 已实现 | 部署/正式验证边界 |
