# 桌面窗口栏与账号退出导航

## 原因与修复

原实现隐藏了 Windows 系统标题栏，却只在 DesktopWorkspace 和国庆专题页绘制窗口按钮。账号页、关于页、资料连接、设置导入导出、文档查看、启动加载/失败及账号数据切换遮挡页使用独立路由或替换导航内容，会失去窗口按钮。首页内的拖动区域还放在内容层下方，不能保证所有页面都能拖动。

现在由 MaterialApp builder 中的 DesktopWindowFrame 统一负责原生窗口操作，放在 Navigator、模态遮挡和账号切换区域之外，预留顶部 32 dp（随桌面令牌缩放）。业务页不再绘制窗口栏。所有独立路由自动覆盖，最小化、最大化/还原、关闭和拖动区域始终可用；窗口边缘保留 6 dp 的调整大小区域。工具提示使用框架自身的 Overlay，不依赖某个路由是否存在。

原来的账号变化处理总是 popUntil 首页，退出登录也因此回到首页。现在先等待旧账号写入与访客数据切换结束，再清理旧导航，Windows 未登录时进入账号登录页；用户可主动返回访客首页，登录成功仍进入当前账号首页。切换期间保留窗口栏，隐藏旧账号业务内容。异步导航读取最新账号状态，避免多个账号变化在同一帧内完成时误用旧状态。

## 验证范围与剩余边界

自动回归覆盖 1100×800 与 2560×1440 窗口、独立账号路由和模态弹窗、加载/失败/账号切换状态、按钮平台调用，以及立即退出和等待旧账号数据写入两种路径；Android 不增加桌面窗口栏。账号、桌面布局、排行榜与响应式回归同时运行。

2026-10-08：相关回归 139 项、主项目全量 511 项通过，静态分析无问题。使用随应用打包的 Noto Sans SC 字体渲染 1280×800 退出后登录页，确认窗口栏在页面上方、表单未被覆盖。Windows Release 通过技能的本地构建入口在 `build/desktop-window-fix/windows/x64/runner/Release` 编译成功，版本 4.1.0+31；保留正在运行的旧实例，Flutter 全局构建目录配置已恢复。本次没有重新生成 APK、Web 构建或上传安装包。

本次没有调整 Android 退出后的导航，仍沿用返回首页。尚未进行真实 Windows 多显示器 DPI 切换、系统窗口边缘拖拽、最大化/还原和系统关窗的人工验收；模拟的平台调用与编译通过不能代替这些检查。外部 PDF 阅读器、文件选择器、Android 安装器等系统窗口由对应程序或系统管理，不属于应用自绘窗口栏。

回滚仅需还原本次窗口框架与导航改动，不影响账号数据格式、NAS 目录或已保存的登录记录。
