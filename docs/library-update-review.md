# 资料更新通知与确认

检查方式、快速/完整检查定义及实际调度频率统一见 [同步与更新检查规范](sync-and-update.md)。本文记录现有确认更新的行为；本轮规范文档不表示周期目录差异比较、自动更新或新进度界面已经实施。

Windows、宽屏 Web 的消息行以按钮语义提供更新入口；Android 与窄屏 Web 的消息列表也可点击。打开后共用 `LibraryUpdateReview`：宽屏用详情弹窗，窄屏用带固定操作区的页面。选择“暂不更新”保留待更新项，之后仍可从通知进入；旧通知没有内存中的待更新清单时重新检查，不能直接应用历史内容。

## 差异与更新

- 以当前缓存目录为比较基准，缺少缓存时使用内置目录。JSON 按规范化结构比较，忽略键顺序；目录变化后继续检查已有资源，避免隐藏同时发生的规则或元数据修改。
- 展示新增桌游、排序/分类变化、停用桌游、新增/停用已登记资料，以及图片、规则书、FAQ、桌游信息等资源分类。评分与人数等有限字段展示前后值；其他字段展示变化类别与文件名，不直接输出协议 JSON、来源网址或凭据。
- 目录为 overlay，缺少条目不表示删除内置桌游。停用依据 `enabled` 或资源登记状态；不删除用户文件。未取得新桌游配置时检查失败，不生成不能应用的清单。`docs/others` 始终排除。
- 文档内容变化依据既有 ETag/Last-Modified/大小探测。没有历史指纹时建立基线，不能证明 PDF/图片内部的逐段差异；不生成未经比较的“修改说明”。
- 确认后复用现有资源传输，资源文件先下载，游戏配置与目录后下载，验证非空及 JSON 结构。原生文件先写临时文件再替换。每个请求仍使用既有 8 秒超时；版本探测最多并发 4 项，检查总预算 2 分钟，更新总预算 15 分钟，在当前请求结束后检查预算。
- 更新期间禁止重复启动。显示已完成/总项数；任一下载或缓存写入失败保留清单和错误，并提供重试。已完成文件可以已写入缓存，失败不是整批事务回滚；当前游戏列表在整批完成后重载。来源或身份变化使旧任务不能报告成功或回填待更新状态。
- 完成后刷新游戏列表、资料索引和图片解析，并将通知改为“资料已更新”。“已读”和“已更新”是不同状态。

## 三端存储与依赖

原生沿用文件缓存和 `_asset_versions.json`。Web 用浏览器 Cache Storage 保存确认更新后的文件体，以逻辑资料路径作为键，不保存 NAS URL 或 Authorization；版本指纹使用现有 `shared_preferences`。游戏配置、规则文档和图片优先读取该缓存，浏览器刷新后仍能使用。浏览器缓存可能被用户或系统清理，配额不足时显示失败；需要 HTTPS 或 localhost，真实 WebDAV 请求仍受 CORS 约束。

浏览器接口直接使用已经在锁文件中的 Dart 官方 `web` 1.1.1（BSD-3-Clause），现明确声明直接依赖，未升级其版本。遵循 [Dart 官方 package:web 指南](https://dart.dev/interop/js-interop/package-web)；缓存封装使用该版本 `service_workers.dart` 的 CacheStorage/Cache 与 `fetch.dart` 的 Response，不自建存储协议。升级跟随 Flutter/Dart 的 JS interop 兼容性验证，原生构建通过条件导入排除浏览器接口。

## 验证与边界

2026-10-07：最终全量 473 项测试通过；更新、资源与清单另有 28 项专项复测通过。覆盖通知点击、取消、重试、重复提交、目录与元数据同时变化、新桌游/资料、停用、归档排除和来源切换；390/1280 dp 两种界面均有行为测试，重试与完成反馈也覆盖 150% 文字缩放。旧通知重新检查覆盖加载、失败重试与无待更新的状态。

最终静态检查、Android Release APK、Windows Debug EXE 和 Web 构建通过。Web 在独立 localhost 夹具中验证 390/1280 dp 通知点击、暂不更新、确认更新、成功反馈，并通过实际浏览器缓存确认刷新后评分仍为更新值。夹具不使用 NAS 凭据；真实 NAS 权限、CORS、Android 真机和 Windows 实际服务器下载尚未实测。构建产物用于验证，未安装或发布。

回滚只需还原本次资料更新控制器、通知入口、差异模型与缓存读取改动，并移除新增 review/diff/browser-cache 文件。原生缓存格式不变，旧版忽略新增浏览器缓存和偏好键。前一轮账户/WebDAV 编辑的改动独立保留。
